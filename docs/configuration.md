# Настройки

[README](../README.md) · [Устройство сервиса](architecture.md) · [Эксплуатация](operations.md)

Конфиг — локальный `config.json` рядом с `index.ts`. Начните с
[`config.example.json`](../config.example.json): он включён в Git, содержит
заглушку Twitch-токена, выключенный AI и `delivery=console_only`.
Значения в таблицах ниже относятся к этому шаблону; существующий приватный
конфиг может отличаться. При пропуске поля код иногда использует другой fallback.

Файл читается при запуске; автоматического перечитывания нет. После правок
конфига перезапустите только приложение командой из [инструкции](operations.md).
Compose монтирует конфиг только для чтения. `.env` влияет на подстановки Compose,
но не заменяет поля `config.json`.

## Канал, токены и транспорт

| Поле | Назначение |
|---|---|
| `channel` | Логин одного канала; в примере `licrige` |
| `accessToken` | Пользовательский OAuth-токен Twitch, префикс `oauth:` необязателен |
| `clientId` | Необязательная проверка соответствия приложению, выдавшему Twitch-токен |
| `refreshToken` | Поле предусмотрено; автоматического обновления Twitch-токена пока нет |
| `transport` | `auto`, `irc` или `eventsub` |
| `ai.accessToken` | Отдельный API-ключ выбранного AI-провайдера |

Для чтения EventSub используется `user:read:chat`, для IRC — `chat:read`.
Отправка через API требует `user:write:chat`, через IRC — `chat:edit`.
В `auto` приоритет у EventSub, кроме режима отправки с доступным только IRC-правом.
Чтение не означает, что у токена есть право записи.

## AI, модель и образ

| Поле | Значение в шаблоне / смысл |
|---|---|
| `ai.enabled` | `false`; включает анализ с платными API-запросами |
| `ai.delivery` | `console_only`; значение `chat` разрешает реальную отправку |
| `ai.provider` | `openrouter`; также поддержан `zai` |
| `ai.baseUrl` | `https://openrouter.ai/api/v1` |
| `ai.model` | `google/gemini-4-argon`; задавайте модель явно |
| `ai.providerRouting.only` | `["google-ai-studio/flex"]`, точные маршруты OpenRouter |
| `ai.providerRouting.allowFallbacks` | `false`; при недоступном маршруте смены провайдера нет |
| `ai.reasoningEffort` | `medium`, мышление для чата |
| `ai.stream.reasoningEffort` | `medium`, отдельное мышление для реакции на эфир |
| `ai.maxTokens` | `3072`, лимит вывода, передаваемый провайдеру |
| `ai.temperature` | `0.6`; применяется к Z.AI, в OpenRouter не отправляется |
| `ai.prePrompt` | Образ и манера; полностью заменяет текст из `default-pre-prompt.ts` |
| `ai.strategy` | `balanced`; альтернативы `streamer-first` и `chat-first` |
| `ai.strategyPrompt` | Дополнительные правила выбранной стратегии |

Проверка конфигурации принимает для OpenRouter `low/medium/high/max`,
для Z.AI `low/high/max`. Для указанной модели Gemini `max` отклоняется.
Проверка готового ответа всегда использует `low`. Пустые/неверные маршруты
OpenRouter и неизвестные поля `providerRouting` вызывают ошибку конфигурации.
Без явной модели fallback OpenRouter в коде остаётся `openai/gpt-6.1-sol`.

## Время, устаревание и паузы

| Поле `ai.*` | Шаблон | Назначение |
|---|---:|---|
| `timeoutSeconds` | 12 с | Максимум ожидания генерации от API |
| `reply.maxAgeSeconds` | 30 с | Предельный возраст сообщения чата для ответа |
| `stream.maxAgeSeconds` | 15 с | Предельный возраст готового фрагмента ASR для реакции |
| `review.timeoutSeconds` | 6 с | Максимум отдельной проверки готового ответа |
| `batch.size` | 12 | Число новых разговорных сообщений для обычного анализа |
| `batch.maxWaitSeconds` | 12 с | Ожидание порции, если сообщений меньше |
| `batch.minIntervalSeconds` | 8 с | Минимум между началами обычных анализов |
| `reply.cooldownSeconds` | 40 с | Общая пауза после инициативной реплики |
| `dialogue.debounceSeconds` | 1 с | Накопление обращений к боту |
| `dialogue.minIntervalSeconds` | 3 с | Минимум между началами анализов обращений |
| `dialogue.windowSeconds` | 120 с | Хранение известных ID собственных сообщений для reply |
| `stream.debounceSeconds` | 2 с | Накопление свежей речи |
| `stream.minIntervalSeconds` | 4 с | Минимум между началами анализов речи |
| `stream.cooldownSeconds` | 10 с | Пауза эфира; после доставки берётся максимум с `reply.cooldownSeconds` |

Возраст считается с поступления сообщения либо готового ASR-фрагмента в процесс,
а не с начала HTTP-запроса. Ожидание в буфере, анализ и проверка расходуют этот
срок. Буферизация Twitch и предшествующее распознавание в возраст ASR не входят.
Свежие события рядом не делают выбранную старую реплику снова актуальной.

Бюджет генерации — минимум `timeoutSeconds` и остатка срока события за вычетом
резерва проверки и 0,5 с. Резерв равен `review.timeoutSeconds`, для эфира
ограничен 4 с. Проверка затем получает только оставшийся срок события.
Например, при эфире 15 с и накоплении 2 с генерации остаётся примерно 8,5 с
до дополнительных затрат. Увеличение одного таймаута API этот срок не расширяет.

Одновременно выполняется один запрос анализа с проверкой. Накопление и интервалы
задают самый ранний запуск, без гарантии немедленного ответа при занятом анализе.
Прямые обращения обходят общую паузу инициативных реплик, но могут получить `skip`.

## Размер ответа и контекст

| Поле `ai.*` | Шаблон | Назначение |
|---|---:|---|
| `reply.maxCharacters` | 160 | Максимальная длина текста модели |
| `reply.maxWords` | 24 | Максимальное число слов |
| `reply.minConfidence` | 0.7 | Минимальная уверенность модели для ответа |
| `context.maxChatMessages` | 40 | Сообщения чата в текущем окне |
| `context.maxSpeechSegments` | 10 | Свежие фрагменты ASR |
| `context.maxAgeSeconds` | 90 с | Возраст текущего контекста, отдельно от срока ответа |
| `context.maxCharacters` | 9000 | Бюджет JSON событий |
| `context.earlierSpeech.maxAgeSeconds` | 300 с | Более ранняя речь как фон разговора |
| `context.earlierSpeech.maxCharacters` | 4000 | Бюджет JSON более ранней речи |

Память пользователей и последние собственные ответы передаются дополнительно.
Старая речь помогает понимать тему, но сама не запускает реакцию и не является
опорой для личных фактов. Длинные ответы отклоняются целиком, без обрезки.

## Память, история и приветствие

| Поле | Шаблон | Назначение |
|---|---:|---|
| `ai.memory.enabled` | `true` | Память работает при включённом PostgreSQL и анализе AI |
| `ai.memory.minConfidence` | 0.85 | Порог предложения памяти |
| `ai.memory.maxItemsPerUser` | 5 | Число загружаемых записей на участника |
| `ai.memory.maxCharacters` | 4000 | Общий JSON-бюджет памяти до 12 активных участников |
| `ai.memory.retentionDays` | 90 | Срок фактов |
| `ai.memory.momentRetentionDays` | 14 | Срок интересных эпизодов |
| `database.enabled` | `true` | Запись расхода, истории, памяти и отметок приветствия |
| `database.history.enabled` | `true` | Аудит решений с контекстом |
| `database.history.retentionDays` | 30 | Срок аудита |
| `greeting.enabled` | `true` | Приветствие при первом подключении за день |
| `greeting.timeZone` | `Asia/Yekaterinburg` | Календарный день приветствия |
| `greeting.messages` | Три короткие фразы | Случайно выбираемый текст без вызова AI |

Приветствие требует `ai.enabled=true`, `delivery=chat`, PostgreSQL и прав записи.
В `--check`, `--once`, `--speech-only` оно отключено.
Переход даты без нового подключения сам по себе не отправляет приветствие.

## Звук, база и логи

`speech.enabled=true` включает звук; `threads=2` ограничивает CPU-потоки модели.
Поддерживаются законченные фразы, `partialResults=false`.
В `speech.vad`: `threshold=0.15`, `minSilenceSeconds=0.5`,
`minSpeechSeconds=0.15`, `maxSpeechSeconds=8`.
Пути `modelDir` и `ffmpegPath` в готовом образе менять не нужно.

Для Compose база: `hostname=postgres`, `port=5432`, `database=twbit`,
`username=twbit`, `passwordFile=/run/secrets/postgres_password`,
`tls=false`, `maxConnections=2`. Администраторский пароль приложению не передаётся.

`LOG_LEVEL` выбирает уровень Pino, `TWBIT_LOG_FORMAT=json` — JSON через Compose.
`LOG_FORMAT` управляет этим непосредственно внутри контейнера, `TZ` —
часовым поясом логов. Часовой пояс приветствия задаётся отдельно в конфиге.
